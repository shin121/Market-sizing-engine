# Privacy, ethics, and limits

This is an aggregate planning engine, not a people-search or decisioning system. Synthetic records must never be presented as real people. Representative keys are opaque synthetic IDs and narrative text is excluded from the analytical feature mart. Contact, precise address, account, device, and direct identifiers are prohibited input; this is a policy and bounded runtime guard, not a claim that arbitrary prose can be proven anonymous.

Age, minors, household composition, income, care burden, and related fields carry restricted classifications. The Python query DSL reads the feature registry and rejects a caller-declared `use_context` of credit, employment, insurance, housing eligibility, education opportunity, or harmful minor advertising; omitted context defaults to aggregate market research. This is only a declared-use gate. A caller can misdeclare intent, so deployment still needs authenticated purpose controls, audit, and downstream enforcement.

The web segment service adds a separate catalog gate: every enabled condition must be registered/queryable and match its namespace, entity unit, operator, data type, and allowed values; `minor_protected` and `restricted_targeting` entries are rejected regardless of the submitted payload. Migration `016` also makes the catalog projection fail closed for guarded/inactive domains, non-allowed behaviors, and `child_person` archetypes without rewriting the immutable source rows. Segment free text/payloads, market-scenario names/factors, comparison payloads, Opportunity mutations, review notes/modifications, research creation, the fully enriched canonical research payload, and provider input/output pass a high-confidence scanner for recognized email, phone, resident-registration, labeled account/financial-account, and detailed street-address patterns. Rejections expose only finding classes. The scanner is intentionally bounded and cannot reliably detect all names, unlabeled identifiers, addresses, or indirect re-identification. Users must not join outputs to identifiable records or infer sensitive traits for individual targeting.

For aggregate release, the Python estimator and web calculation persistence suppress derived `person`, `child_person`, and `household` results whose raw weighted Base is below 10. Suppressed records expose neither count/share/interval values nor reconstructable factor values; they retain `small_sample`, status, and safe nonnumeric provenance. Python exempts only exact baseline matches carrying explicit registered official-direct method provenance; an exact weighted/derived cell is not exempt. Its sanitizer runs both before persistence and after load. Web reuse creates a separate suppressed query snapshot, and migration `018` makes five release-safe projections plus downstream view rewrites the canonical trusted-application path for estimate detail, saved segments, comparison, Opportunity, research inputs, scenario creation, search, and export. Those views also remove value-bearing prose, evidence locators, and reconstruction hashes. `establishment`, `enterprise`, and Base=10 are outside the threshold.

Migration `018` is defense in depth, not a hard database-confidentiality boundary: both runtime roles still have broad raw-table `SELECT`, so credentials must remain confined to reviewed server repositories or be narrowed before arbitrary-SQL use. Subtype/allocation detail is also a future-row residual: current data has zero human-unit subtype allocations with Base below 10, but its repository still reads raw allocation values. No direct evidence-backed axis → subtype mapping exists; showing the two layers together must not imply an observed joint.

Commercial needs, objections, and channel preferences in archetype profiles are disclosed inferences. They require research validation and cannot be stated as observed behavior. The 1,440 archetypes overlap; addition without overlap evidence can overcount. Enterprise, establishment, household, and person counts are not interchangeable.

Known limits include missing own-website joints, incomplete five-year histories, uncalibrated synthetic household joints, no Nemotron age-19 weight, sparse evidence outside the vertical slice, reliance on truthful `use_context` declaration, high-confidence-only identifier detection, broad runtime raw-table read grants, and the future-row subtype-allocation release residual. See `reports/validation_gaps.md`.
