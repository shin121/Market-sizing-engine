# Minors and households

The official minor frame contains 19 exact-age cells for ages 0–18 from the 2024-12 resident-registration table, totaling 7,324,873. A deterministic approximately 1:100 sample creates 73,249 synthetic minor records. Age-specific weights reconstruct every official age cell exactly up to floating-point tolerance.

Separately, the 2024 Census reports 4,517,000 households with children age 18 or younger. The synthesis creates 45,170 weighted child-household records and assigns each synthetic minor to a synthetic household and guardian key. There are no orphan links. Household type, geography cluster, dual-income flag, sibling assignment, and guardian key are synthetic—not observed joints—and cannot support factual prevalence claims.

School stage is derived from age and is not enrollment status. No names, addresses, contacts, accounts, devices, or real minor identities are present in the synthetic frame. Minor-related features are tagged `minor_protected`. The Python query DSL checks the caller-declared `use_context` against the feature registry and rejects the listed harmful-minor-advertising and eligibility contexts. This is a declared-use gate: it cannot detect a caller that misstates its real purpose and is not a substitute for downstream authorization or policy enforcement. Separately, migration `016` projects guarded-domain and `child_person` catalog rows as `minor_protected` and non-queryable, and the web segment service rejects every enabled `minor_protected` or `restricted_targeting` condition while failing closed on unknown/non-queryable/mismatched entries. A high-confidence scanner also rejects recognized obvious identifiers in implemented segment, scenario, comparison, Opportunity, review, research, and provider payloads, but it is not universal real-name or PII detection.

The runtime release guard suppresses a **derived** `person`, `child_person`, or `household` result when its raw weighted Base is below 10. Python returns `status=suppressed` with count/share/interval and reconstructable factor values removed; only an exact baseline match with explicit registered official-direct method provenance is exempt, so an exact weighted human Base of 5 is suppressed. A value-free sanitizer runs before persistence and again after every result load. Web calculation persists a separate workspace-owned suppressed snapshot with null count/share/component values, a value-free `result_summary`, and a `small_sample` gap while retaining safe nonnumeric lineage. Migration `018` additionally classifies every human-unit Base-below-10 estimate at the trusted-application read boundary and redacts downstream detail, comparison, Opportunity, research, scenario, and export payloads without rewriting registered controls. `establishment`/`enterprise` and Base exactly 10 are outside the threshold. This is not hard database confidentiality while runtime roles retain raw-table `SELECT`, nor proof that a falsely declared use is safe.

Different Census and resident-registration universes/dates are preserved. The missing official child-count × household-type × guardian-structure joint is a high-priority gap. Details are in `reports/minor_household_synthesis.md`.
